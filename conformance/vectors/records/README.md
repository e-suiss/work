# Record format vectors

Golden vectors for the Work record format: deterministic CBOR, digests, `SignedRecord`, `LedgerEnvelope` and `GenesisEnvelope`. The schema is [`work-record.cddl`](../../cddl/work-record.cddl); it describes protocol 1.0 only, so a record of another protocol version fails it by design and is quarantined by a decoder that reads `versions.protocol` before anything else (P-87, P-94). Every file here is generated by [`gen/gen.py`](gen/gen.py) (Python standard library only); do not edit the JSON by hand.

```
just vectors         # regenerate into target/ and fail if any file differs
just vectors-write   # regenerate in place
just cddl            # validate every record, envelope, genesis and digest vector with the Ruby cddl gem (0.12.14)
```

`just cddl` uses `cddl` from `PATH`, or the binary named by `CDDL`; without it the recipe skips with a message.

## Case format

- `hex` is the normative input. All hex is canonical CBOR unless the case exists to test non-canonical input.
- `decoded` (record, envelope and genesis cases) is a JSON projection of the decoded value, for tests that run before a CBOR decoder is available: maps become objects, byte strings become lowercase hex strings, text stays text, integers are JSON numbers, or decimal strings beyond ±2^53.
- `diag` is CBOR diagnostic notation, for reading only.
- `context` holds verifier inputs that are not record bytes:
  - `origin`: `direct` or `automation`, supplied by the Work service (T-66, T-68);
  - `actor_type`: the envelope's `ActorTypeAnnotation`: `author` is `[type, source]` of the author from the Access identity binding (P-12), and `on_behalf_of`, present when the record has an `on_behalf_of` chain, holds one entry per party in chain order (INV-18);
  - `understood_extensions`: the `ExtKey`s this verifier implements (P-19, P-69);
  - `recorded_at`: the ledger time, present when the record carries `params.effective_at` (P-80);
  - `tag_allowlist`: CBOR tags allowed at this position (`cbor-canonical.json` only).
- `expect.outcome` is `accept`, `reject` or `quarantine`; `reject` and `quarantine` carry a `reason` code, except the `genesis.json` rejections whose code P-100 does not fix yet.
- `cddl` is `fail` when `work-record.cddl` alone rejects the bytes and `pass` when a kernel rule decides the outcome (P-76). The per-subtype `params` maps of P-92 are written in the CDDL, but the open Practice alternative of `DeclarationTyped` also matches core subtypes, so a missing or mismatched core `params` key passes the CDDL and the kernel rejects it. Likewise `LedgerEnvelope.pos` is any `uint` in the CDDL; that position 0 holds only the genesis is a kernel rule (P-100): the kernel picks the schema by `pos`, so a genesis at another position fails `schema:required_field` and an envelope at position 0 fails `schema:unknown_core_field`.
- Until the Access Party reference byte form is fixed (P-67, OQ-34), `PartyRef` is any 1 to 255 byte text, so any such string also passes `ParamScalar` in the CDDL; the kernel applies the subtype schema.
- `rules` lists the spec IDs the case pins.

## Placeholders

- Digests labelled `work-vector:*` are SHA-256 of placeholder ASCII, not of real objects.
- `proof_commit` values are placeholders until signed vectors exist; the rule is SHA-256 of the full tagged `WorkRecordCose` bytes as received (P-75, P-76).
- `PartyRef` values and the COSE code points `-19` and `-9` follow Access once the Party reference byte form is fixed (P-67, OQ-34).
- The genesis rule is fixed (P-100): every record names the LedgerID of `genesis.json` `genesis/accept`, and the envelope chain starts at position 1 with `prev` set to the genesis leaf hash. The genesis `versions.schema` is the `Digest` of the `work-record.cddl` bytes, so any change to the schema changes the LedgerID and every record vector; the `nonce` is a `work-vector:*` placeholder, in production it comes from the `Rng` port.
- Practice namespaces are `https://procurement.example/ns/` and `https://clinic.example/ns/`.

## Hashes and domain separation

| Value | Computation | Prefix |
|---|---|---|
| Record ID | `SHA-256(det-CBOR(SignedRecord))`, the digest of the COSE payload (P-79) | none |
| LedgerID | `SHA-256(det-CBOR(GenesisEnvelope))` as a `Digest` (P-67, P-100, Access CR-1); the CloudEvents `ledger` extension is its 32 bytes in hex (P-98) | none |
| Leaf hash | `SHA-256(0x00 ‖ det-CBOR(LedgerEnvelope))`, and the same over `GenesisEnvelope` at position 0 | `0x00` |
| Body commitment | `SHA-256(0x03 ‖ salt ‖ det-CBOR([name, media_type, content]))`, 32-byte salt from the `Rng` port, fresh per part (P-68, P-101) | `0x03` |
| `proof_commit` | `SHA-256(WorkRecordCose bytes as received)` (P-75, P-76) | none |

The prefixes are the `suiss-crypto` values (P-101): `0x01` is the RFC 9162 interior node and `0x02` the field commitment, which Work does not use.

## Reason codes

| Code | Meaning |
|---|---|
| `malformed_cbor:<detail>` | Not well-formed CBOR (`truncated`, `trailing_bytes`, `invalid_utf8`) |
| `non_canonical_cbor:<detail>` | Well-formed but not deterministic: `non_preferred_argument`, `unsorted_map_keys`, `duplicate_map_key`, `indefinite_length`, `tag_not_allowed`, `float_not_in_profile`, `simple_not_in_profile` |
| `limit_exceeded:<limit>` | Structural or CDDL bound (`depth`, `items`, `string`) or Work semantic (`basis`, `on_behalf_of`, `relations`, `concerns`, `request`) limit; a semantic limit's own code wins (P-91) |
| `schema:<detail>` | Schema mismatch (`kind`, `relation`, `required_field`, `unknown_core_field` for an unknown key in the record or any closed core map, `empty_optional_list`, `empty_optional_map`, `type_uri`, `ext_key`, `params` including a missing, forbidden or mismatched P-92 key, `digest_alg`, `digest_length`, `ingest`, `container`) |
| `non_canonical_set_order:<field>` | `basis`, `concerns`, `critical` or the `visibility` party list not sorted by encoded bytes or not duplicate-free |
| `duplicate_entry:<field>` | Repeated entry in `relations`, `evidence`, `correlation` or `on_behalf_of`, repeated `body` part name, or the author or a principal named in the `visibility` party list |
| `visibility_no_work` | `see: "work"` with empty `concerns` |
| `authority_missing` | Declaration without `authority` |
| `capacity_missing` | Declaration without `capacity` (P-91) |
| `capacity_mismatch` | `capacity` and `on_behalf_of` disagree |
| `unattributed_automation` | `origin = automation` but the author is not an Access-bound system Party or `basis` is absent |
| `unmapped_extension_value` | Core-namespace value outside the catalog, or a Practice value with no mapping in the pinned Practice |
| `retroactive_declaration` | `params.effective_at` earlier than `recorded_at` |
| `extension_critical_dangling` | `critical` names a key that is not in `ext` |
| `extension_critical_unknown` | `critical` names a key the verifier does not understand (quarantine) |
| `protocol_version_unknown` | `versions.protocol` has no rule set in this verifier; no other rule is applied (quarantine) |
| `signature:<detail>` | `alg_not_allowed`, `invalid`, `high_s`, `non_canonical_ed25519`, `small_order_key`, `kid_unknown`, `header_profile` |
| `producer_missing` | Agent-authored record without `producer` (P-15) |
| `envelope_mismatch:actor_type` | The `actor_type` annotation has a different number of `on_behalf_of` entries than the record's chain (P-12, INV-18) |
| `supersedes_kind_mismatch` | A `supersedes` target of another kind; derivation decides it, so no record vector carries it (P-90) |
| `author_signature_missing`, `auth_context_missing`, `duplicate_version`, other `envelope_mismatch:<field>` | Used by the planned files below |

A code may carry a namespaced sub-code, `<code>:<absolute HTTPS URI>`; a verifier that does not know the sub-code reads the parent code (P-71, P-93). The `params` reason codes of `decline`, `cancel` and `notice` take the same form.

## Files

| File | Cases | Rules |
|---|---|---|
| `cbor-canonical.json` | 39: 13 accept, 26 reject (one generated from `generator`) | P-5, P-6, P-7, P-72, Access CR-10 |
| `digest.json` | 6: 4 computations, 2 reject (`cddl: fail`) | P-5, P-6, P-11, P-17, P-67, P-68, P-79, Access CR-1 |
| `genesis.json` | 9: the genesis with its LedgerID and leaf hash (accept); 6 genesis rejects (`cddl: fail`): `prev`, `ledger` or `record` present, `nonce` missing, a 31-byte `nonce`, `pos: 1`; 2 envelope rejects: `pos: 0` (`cddl: pass`) and position 1 without `prev` (`cddl: fail`) | P-100, P-11, P-18, P-27, P-67, P-72, C-35, T-32, Access CR-1 |
| `records.json` | 11 records and 11 envelopes chained from the genesis at positions 1 to 11, all accept | P-9…P-19, P-21, P-24, P-67…P-85, P-92, P-93, P-100, C-5, C-16, C-27, C-29, E-13, EV-3, EV-4, EV-21, EV-24, INV-20, ST-10, ST-12, ST-27, T-66, T-68 |
| `records-quarantine.json` | 5 records and 5 envelopes, quarantine: 2 `extension_critical_unknown` (`cddl: pass`), 3 `protocol_version_unknown` (`cddl: fail`) | P-18, P-19, P-69, P-87, P-94, C-5, T-4 |
| `records-reject.json` | 142: 56 `cddl: fail`, 86 `cddl: pass` | P-7, P-10, P-12, P-13, P-14, P-15, P-33, P-67, P-69…P-85, P-91, P-92, P-93, C-25, C-27, EV-3, EV-21, INV-18, T-65, T-66, T-68 |

The accept records are an agent promise on behalf of a principal; an Act of the core `action` subtype that fulfills a promise; an automation-originated system Observation; a human amendment with `params.effective_at`, a pinned Practice and an extension; a private Practice comment Claim; a Practice Claim with a critical extension; a decline with a catalog reason code visible to one named Party; a decision gate with its gate form, address, deadline and criterion; a wait with a pinned Practice condition type and an explicit `none` deadline; a cancel with a namespaced reason sub-code; and a Practice Claim with a digest and a list in `params` and a pinned Practice qualifier on `references`.

The rejections cover, besides single-field mutations of those records: `capacity_missing`; `producer_missing`; an actor-type annotation with the wrong number of rings; every required, forbidden and mismatched P-92 key; reason sub-codes with an unknown parent or a non-URI sub-code; CDDL item and string bounds; `search` or `agent_context` written as `true`; an audience outside the vocabulary; an unknown key in each closed core map; a core qualifier and an unpinned Practice qualifier on `references`; an unpinned Practice Act subtype and `derived_from` role; one invalid endpoint per relation, a three-element endpoint and a non-text qualifier; and a Declaration without `authority` for one subtype per family: `request`, `cancel`, `notice`, `assign`, `renew_lease`, `gate_decision`, `stop_request`, `stop_response`, `open_condition`, `withdraw_condition`, `resume_after_stop`, `practice_adoption`, `disclosure`, `queue_definition`, `control_lease`, `handoff_note`, `conflict_resolution`, `admission`, `autonomy_policy`, `implicit_acceptance_terms`, `waiver`, `attention_request` and `acknowledgement` (`promise` and a Practice Declaration were already there). Non-human authors' envelopes carry `proof_commit`; the human author's carry `auth_context`.

Planned files, which need a test signing key or later stages: `cose-sign1`, `record-kinds`, `authority-capacity`, `relations`, `extensions`, `enums`, `limits`, `attribution`, `supersession`, `evidence`, `envelope` (P-76).
