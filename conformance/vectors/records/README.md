# Record format vectors

Golden vectors for the Work record format: deterministic CBOR, digests, `SignedRecord` and `LedgerEnvelope`. The schema is [`work-record.cddl`](../../cddl/work-record.cddl). Every file here is generated by [`gen/gen.py`](gen/gen.py) (Python standard library only); do not edit the JSON by hand.

```
just vectors         # regenerate into target/ and fail if any file differs
just vectors-write   # regenerate in place
just cddl            # validate every record, envelope and digest vector with the Ruby cddl gem (0.12.14)
```

`just cddl` uses `cddl` from `PATH`, or the binary named by `CDDL`; without it the recipe skips with a message.

## Case format

- `hex` is the normative input. All hex is canonical CBOR unless the case exists to test non-canonical input.
- `decoded` (record and envelope cases) is a JSON projection of the decoded value, for tests that run before a CBOR decoder is available: maps become objects, byte strings become lowercase hex strings, text stays text, integers are JSON numbers, or decimal strings beyond ±2^53.
- `diag` is CBOR diagnostic notation, for reading only.
- `context` holds verifier inputs that are not record bytes:
  - `origin`: `direct` or `automation`, supplied by the Work service (T-66, T-68);
  - `actor_type.author`: `[type, source]` of the author from the Access identity binding (P-12);
  - `understood_extensions`: the `ExtKey`s this verifier implements (P-19, P-69);
  - `recorded_at`: the ledger time, present when the record carries `params.effective_at` (P-80);
  - `tag_allowlist`: CBOR tags allowed at this position (`cbor-canonical.json` only).
- `expect.outcome` is `accept`, `reject` or `quarantine`; `reject` and `quarantine` carry a `reason` code.
- `cddl` is `fail` when `work-record.cddl` alone rejects the bytes and `pass` when a kernel rule decides the outcome (P-76).
- `rules` lists the spec IDs the case pins.

## Placeholders

- Digests labelled `work-vector:*` are SHA-256 of placeholder ASCII, not of real objects.
- `proof_commit` values are placeholders until signed vectors exist; the rule is SHA-256 of the full tagged `WorkRecordCose` bytes as received (P-75, P-76).
- `PartyRef` values and the first envelope's all-zero `prev` follow Access once the Party reference byte form and the genesis rule are fixed (P-67, OQ-34).
- Practice namespaces are `https://procurement.example/ns/` and `https://clinic.example/ns/`.

## Hashes and domain separation

| Value | Computation | Prefix |
|---|---|---|
| Record ID | `SHA-256(det-CBOR(SignedRecord))`, the digest of the COSE payload (P-79) | none |
| Leaf hash | `SHA-256(0x00 ‖ det-CBOR(LedgerEnvelope))` | `0x00` |
| Body commitment | `SHA-256(0x02 ‖ salt ‖ det-CBOR([name, media_type, content]))`, 32-byte salt from the `Rng` port, fresh per part (P-68) | `0x02` |
| `proof_commit` | `SHA-256(WorkRecordCose bytes as received)` (P-75, P-76) | none |

`0x01` is the Access field commitment; Work does not use it.

## Reason codes

| Code | Meaning |
|---|---|
| `malformed_cbor:<detail>` | Not well-formed CBOR (`truncated`, `trailing_bytes`, `invalid_utf8`) |
| `non_canonical_cbor:<detail>` | Well-formed but not deterministic: `non_preferred_argument`, `unsorted_map_keys`, `duplicate_map_key`, `indefinite_length`, `tag_not_allowed`, `float_not_in_profile`, `simple_not_in_profile` |
| `limit_exceeded:<limit>` | Structural (`depth`, `items`, `string`) or Work semantic (`basis`, `on_behalf_of`, `relations`, `concerns`, `request`) limit |
| `schema:<detail>` | Schema mismatch (`kind`, `relation`, `required_field`, `unknown_core_field`, `empty_optional_list`, `empty_optional_map`, `type_uri`, `ext_key`, `params`, `digest_alg`, `digest_length`, `ingest`, `container`) |
| `non_canonical_set_order:<field>` | `basis`, `concerns`, `critical` or the `visibility` party list not sorted by encoded bytes or not duplicate-free |
| `duplicate_entry:<field>` | Repeated entry in `relations`, `evidence`, `correlation` or `on_behalf_of`, repeated `body` part name, or the author or a principal named in the `visibility` party list |
| `visibility_no_work` | `see: "work"` with empty `concerns` |
| `authority_missing` | Declaration without `authority` |
| `capacity_mismatch` | `capacity` and `on_behalf_of` disagree |
| `unattributed_automation` | `origin = automation` but the author is not an Access-bound system Party or `basis` is absent |
| `unmapped_extension_value` | Core-namespace value outside the catalog, or a Practice value with no mapping in the pinned Practice |
| `retroactive_declaration` | `params.effective_at` earlier than `recorded_at` |
| `extension_critical_dangling` | `critical` names a key that is not in `ext` |
| `extension_critical_unknown` | `critical` names a key the verifier does not understand (quarantine) |
| `protocol_version_unknown` | `versions.protocol` has no rule set in this verifier; no other rule is applied (quarantine) |
| `signature:<detail>` | `alg_not_allowed`, `invalid`, `high_s`, `non_canonical_ed25519`, `small_order_key`, `kid_unknown`, `header_profile` |
| `producer_missing`, `author_signature_missing`, `auth_context_missing`, `duplicate_version`, `envelope_mismatch:<field>` | Used by the planned files below |

## Files

| File | Cases | Rules |
|---|---|---|
| `cbor-canonical.json` | 39: 13 accept, 26 reject (one generated from `generator`) | P-5, P-6, P-7, P-72, Access CR-10 |
| `digest.json` | 6: 4 computations, 2 reject (`cddl: fail`) | P-5, P-6, P-11, P-17, P-67, P-68, P-79, Access CR-1 |
| `records.json` | 7 records and 7 chained envelopes, all accept | P-9…P-19, P-21, P-24, P-67…P-85, C-5, C-16, C-27, C-29, E-13, EV-3, EV-4, EV-21, EV-24, INV-20, T-66, T-68 |
| `records-quarantine.json` | 3 records and 3 envelopes, quarantine | P-18, P-19, P-69, P-87, C-5, T-4 |
| `records-reject.json` | 64: 28 `cddl: fail`, 36 `cddl: pass` | P-10, P-13, P-14, P-33, P-69…P-85, T-65, T-66, T-68 |

The accept records are an agent promise on behalf of a principal; an Act of the core `action` subtype that fulfills a promise; an automation-originated system Observation; a human amendment with `params.effective_at`, a pinned Practice and an extension; a private Practice comment Claim; a Practice Claim with a critical extension; and a decline with a catalog reason code visible to one named Party. Non-human authors' envelopes carry `proof_commit`; the human author's carry `auth_context`.

Planned files, which need a test signing key or later stages: `cose-sign1`, `record-kinds`, `authority-capacity`, `relations`, `extensions`, `enums`, `limits`, `attribution`, `supersession`, `evidence`, `envelope` (P-76).
